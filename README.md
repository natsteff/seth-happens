## How to add as a mobile app

**For the best mobile experience, use the Home Screen app. This is the only recommended mobile play mode.** Add the game using the steps below, then launch its icon and play in landscape. Direct browser-tab play on phones may have persistent browser bars, reduced play space or uneven centering; further fixes for that mode are not planned.

Home Screen launch removes browser controls in supported app mode, giving the game more usable space and avoiding accidental browser interactions. Owner testing confirmed that this resolved gameplay and centering issues encountered in Chrome on iOS. It also provides one-tap access. Game features remain the same; this is not a promise of faster performance on every device.

On iPhone, open the game in Safari, tap **Share → Add to Home Screen**, enable **Open as Web App** if offered, then **Add**. Launch the new icon and rotate to landscape. Chrome on iPhone also offers **Share → Add to Home Screen**; use Safari if unavailable. Android Chrome offers **Add to Home screen / Install app** in its menu when supported. Browser labels vary; a normal browser tab may retain its address bar.

The game supplies its own Seth / BEER RUN app icon for iPhone/iPad and Android, plus a simplified Seth favicon for browser tabs. Your browser chooses the appropriate icon when you add the game. Existing Home Screen icons may need to be removed and added again to pick up updated artwork.

Auto update on launch is enabled by default in the mobile menu. A confirmed newer release reloads immediately, even if a run is in progress. You can disable automatic checks or use Check for updates manually; neither clears scores or settings. An older cached release must first load a version containing this feature.

This is an online Home Screen web app, not an offline download. Scores and preferences may be separate between browsers and the Home Screen app. See [Apple instructions](https://support.apple.com/guide/iphone/iphea86e5236/ios) and [Chrome instructions](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DiOS).

## Controls

| Action | Key |
| --- | --- |
| Move | A / D or ← / → |
| Jump | Space, W or ↑ jumps immediately; press twice within 0.3s for Mega Jump. Holding has no extra effect |
| Sprint | Hold Shift |
| Optional controller | Left stick/D-pad move; A/Cross jump (double-press Mega Jump); RT/R2 sprint; X/Square interact; B/Circle recall; Menu/Options pause |
| Pause / resume | P or Pause button |
| Photo / finish | F |
| Return to a missed photo | B |
| Sound | S |
| Fullscreen | V or fullscreen button; Esc exits |
| Restart | Hold R |

Floor 01 is the first rooftop. Returning to a lower rooftop is safe. Missing the rooftops and falling toward the road from Floor 02 or higher screams, costs one fall penalty, and retries the last rooftop. Dropping from Floor 01 to the road remains safe.

Keyboard remains the default and stays active with a controller connected. Pair a supported standard-layout controller through the operating system, focus the game and press a button; release controls to neutral before play. Disconnecting the active controller pauses play. Use keyboard/mouse for menus, restarting and high-score name entry. Actual device/browser compatibility still needs hardware testing.

Rolling and walking obstacles patrol the whole floor. Pianos, anvils, window AC units and beer coolers drop at distinct intervals in the middle of their platforms. Watch their warning and aftermath, then choose your jump. Falling objects can squish you during descent; once landed they are safe to touch but solid, so jump over them.

Beer pickup requires **Action** (mobile), **F** (keyboard) or the controller interact button while next to the six-pack. Running past it does not collect it.

### Mobile touch controls

Portrait mode groups the complete game view and touch controls together, with an accessible menu and a reminder to rotate. Landscape remains the recommended way to play. Mobile instructions use Action and menu names rather than keyboard letters. The mobile HUD shows the track number/title and audio state; change music through the menu.

**Launch the Home Screen app in landscape for mobile play**—see [How to add as a mobile app](#how-to-add-as-a-mobile-app). Phones and tablets are offered optional touch controls on their first visit. The game remembers touch versus keyboard/controller choice and restores saved controls on later launches; existing saved customization also counts as completed setup. Controls remain available through **Touch controls**. Home Screen launches omit redundant installation advice. Clearing storage can reset setup; browser and Home Screen storage may be separate. The game keeps its full framing, with translucent controls over the lower corners. Direct mobile browser-tab layout issues are not being pursued further.

Slide the left pad left or right without lifting your thumb; the center stops movement and either outer edge activates sprint. Use the round **Jump** button (double-tap within 300ms for Mega Jump) and **Action** for beer pickup, photos, finish and elevator. Recall returns to the earliest missed photo; when delivering with photos missing, choose delivery, Recall, or keep playing. Beer is required to finish normally; photos remain optional. Release the pad to stop.

The **☰** button pauses play and opens the menu: Resume, control customization, restart, scores, sound, music/volume/tracks and fullscreen exit. Keyboard and standard controllers remain available. Owner testing confirmed successful iOS Home Screen gameplay; Android device acceptance remains pending.


Expanded/fullscreen touch play hides page scrollbars and keeps controls away from screen edges. Gameplay touch gestures are reserved for the game; menus and score entry keep normal scrolling and input behavior. Leaving expanded view restores page scrolling.

Browser-owned address/tool bars can remain when native fullscreen is unavailable. For a view without browser bars on iPhone, use Safari’s **Share → Add to Home Screen**, enable **Open as Web App** where offered, and launch that icon. Other browsers may offer a similar Home Screen option. The game includes a standalone web-app manifest; it still loads online. See [Apple’s Home Screen instructions](https://support.apple.com/guide/iphone/iphea86e5236/ios).

Mobile controls offer **Default** walking arrows (sprint off by default), **Sliding Speed Runner**, or **Game Stick**. Choose **Customize Controls** before play or in the mobile pause menu. Arrow spacing has five settings; your choice is saved in this browser. **Double-tap to sprint** is optional and off by default for Default arrows: tap the same arrow twice within 250 ms, holding the second press to sprint. Release or change direction to cancel; the next press walks normally. Enable it in Customize Controls. Game Stick vertical movement does not trigger actions. Select **Start Game** to begin the intro; gameplay starts after the intro finishes.

## Music radio

Five backing tracks are selectable in the SETH FM bar. **Arcade Staircase** is default; keys **1–5** select songs, **0** turns music off, and **[ previous · ] next** select previous/next with wraparound. New players start at **75%** music volume; preferences persist between sessions. The music slider reaches silence without changing voices/effects. **S** mutes all sound. Gameplay songs loop and pause with play/score dialogs. At run end, outcome music replaces them; completion music continues through score entry. Music starts after the intro and appears in fullscreen too.

## Scoring and records

- Finish within **120 seconds**: 1,000 base points.
- Each photo: +250; photos first recovered after reaching floor 26: +125.
- Deliver the six-pack: +500.
- Each fall, squish or bump: −10, counting each incident once.
- Finish under **120 seconds**: +100 for each whole second saved. A 90-second finish earns +3,000. Fractional seconds round up before calculating the bonus.
- At 120 seconds, the run fails and no score is saved.
- Intro and high-score dialogs pause the clock. P pauses gameplay, countdown, animations and audio. Resume continues from the same point.

The countdown displays seconds (120s → 0s), and run times in score screens use seconds. Existing scores and point totals are preserved. Historical finishes at or above the new limit are labelled “previous time limit”; they are not deleted or treated as newly valid runs.

## Optional server high scores

High Scores opens your existing local browser list directly by default, including on the **Play Now** GitHub Pages version. Server scores default off in `public/game-config.json` (deployed as `game-config.json`).

Server installations can enable **Server High Scores** alongside **This PC High Scores**. New runs attempt both lists, with separate save results. Existing local records automatically sync to that deployment’s server when enabled, without deleting local scores or duplicating imports. Failed syncs retry when reopening scores or reconnecting. Older untimed runs retain their original score and date without an invented timer bonus. Each hosted copy has its own shared records.

Server-wide scores require a running score service; GitHub Pages cannot provide it. See [server setup](docs/leaderboard-server.md). Clearing acts on the selected list only and always requires confirmation. GitHub Pages local scores do not require a password; other installations are password-protected by default, with separate local/server configuration options.

## High-score entry and clearing

Successful names are remembered in this browser: use Save as the last name or Change name. New/changed names use a compact keyboard-aware form; Return saves, and the full record list appears afterward. Full names remain supported up to 16 characters. This preference is separate from stored scores.

On github.io, clearing this device’s browser scores requires confirmation but no password. Other deployments require the existing clear password by default; owners can set `clearPasswordRequired:false` in `game-config.json` for local scores. Shared leaderboard clearing has its own server-side setting in `server/config.json` and cannot be unlocked by the client hostname. Alternate installations should retain protection unless intentionally opting out. Clearing one list never clears the other.
